## 任务提示词

以下为本题完整的 User Prompt 原文，两次执行必须使用完全相同的文本。

我们要在内存里做多变量原子修改，用锁拼起来容易死锁也难组合。请从零实现一个软件事务内存（STM）组件。仓库目前只有一个空的 Maven 工程（pom.xml 只声明 JUnit 5 与 AssertJ）。要求：1) 提供事务引用（可读写）与原子块入口，块内的读写都记录在事务日志里；2) 提交时做乐观冲突检测：读集内任一引用在事务期间被他人写过即判定冲突；3) 冲突时整个原子块自动重试，并限制重试次数与总时长，超限抛出明确的失败异常；4) 事务内对同一引用的多次写只保留最后一次，回滚时不得影响其它事务的已提交修改；5) 支持只读事务：只读块不产生写冲突，需有测试证明两个只读事务可并发通过；6) 冲突检测要落实到具体引用：失败信息需指出是哪个引用、被哪个事务改写；7) 提供统计：事务数、提交数、冲突重试次数与平均重试轮数；8) 测试覆盖原子提交、冲突重试、只读并发、重试上限、写合并与统计；`mvn -q verify` 一条命令跑通。

## 实现说明（分支 A）

STM 组件位于 `src/main/java/com/example/gsb/stm/`：

- `Stm`：运行时入口。`atomically(...)` 执行读写事务，`readOnly(...)` 执行只读事务，`stats()` 返回统计快照。
- `StmRef<T>`：事务引用，记录值、版本号与最后写入事务 id。
- `Transaction`：事务日志（读集 = 引用→版本，写集 = 引用→待提交值，重复写只保留最后一次）。
- `StmConfig`：重试上限与总时长限制；超限抛 `StmTransactionFailedException`，其 cause 为 `StmConflictException`（指明冲突引用与改写它的事务 id）。
- `StmStats`：事务数、提交数、失败数、冲突重试次数与平均重试轮数。

```java
Stm stm = new Stm();
StmRef<Integer> a = stm.newRef("a", 100);
StmRef<Integer> b = stm.newRef("b", 0);
stm.atomically(tx -> {
    tx.write(a, tx.read(a) - 50);
    tx.write(b, tx.read(b) + 50);
    return null;
});
```
